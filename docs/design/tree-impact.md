**Reading.** (1) The targets 45-55 random / 65-75 FOCUS for both heroes with a gap <= 5 cannot be met by the shared tree at any ceiling up to x3: **Wren plateaus at about 20-32 random / 46-48 FOCUS whatever the tree gives** (1.13x, 2x, 3x and 2x faces all land inside noise), while Elias climbs from 59 / 68 (Lever 1) to 67 / 79 (x2) and saturates near 70-73 / 70-80. The tree is not asymmetric (the two weapon clusters are identical in size and PE; Wren's tree bonus is in fact larger: wolf power +13.7 %, speed +8.3 % vs orbit power +8.3 %, size/speed +3.2 %); the gap is hero baseline (no tree, all gates: Wren 2 %, Elias 8 %, starter 4 vs 19). Full-tree diagnostic (12 seeds, random pick, x2 data): Wren deals 175k damage per run, Elias 291k (-40 %); the Elder Treant dies in 2 of 12 Wren runs vs 7 of 12 Elias runs; Elias actually takes MORE hits (hurtBy per run: wolf 270 vs 118, root-crawler 95 vs 44) and survives on sustain (Hearts, Last Light). So Wren's wall is damage output, not survival, and the tree's few-percent stat bonuses cannot close a 40 % output gap. A Wren-only fix (wolf damage / bleed) is a hero-balance chunk for the FINAL retune, not tree data. (2) **The hero average at x2 is on target**: random (25 + 67) / 2 = 46, FOCUS (48 + 79) / 2 = 64, versus 45-55 / 65-75; at Lever 1 it is 42.5 / 57.5 (below). So x2 is the factor that centres the pair, and a hero-side fix that closes the gap by moving both toward the middle lands both inside the band. If Matt prefers Elias alone in band (random <= 55), Lever 1 (x1.13) already gives 59 / 68. (3) Real power is small: the x2 full tree is +1.3 % global damage, +2.5 % cast speed, +3.7 % area, +6.3 % max HP, +13.7 % wolf power; tiny stat changes move Elias a lot because he sits near the win threshold, and move Wren not at all because she is far below it.

## B. Dead / padding nodes: outcome

- The analytic audit flagged 54 nodes as dead (marginal PE < 0.03). They were dead individually because each weapon pool (S about 21-24 against a cap of 7 / 8.6) threw away most of its faces. After the x2 pool cap (17.2) **none of the 54 is dead any more**: each weapon-cluster knot is worth 0.05 PE (pool total 0.9 PE per cluster, 11 nodes) and is classed `weak`; the only 'dead' rows left (Lodestar, Swift Spirits) were misclassified: they are uncapped utility effects (magnet drops, summon speed) and are now `option`.
- **Nothing was retired.** The cluster outline is a fixed 11-slot template tied to the emblem art (`emblems/*.json`: 11 outline points, apex, 3 sockets, 1 heart; kinds fixed per slot), so removing a knot means redrawing the constellation; the ring nodes (rings, tools) have no padding (the weakest are the six reroll / banish nodes at 0.1 sustain PE, kept on purpose as felt choices). Merging was done the other way round: the 11 nodes with the most visible effect were strengthened (section C) instead of deleting padding.
- Open item (not changed here): `su_swift` Swift Spirits (+4 % summon speed) and any `@magic` speed effect sit in the uncapped 'util' pool (`summonSpeed` / `magicSpeed`), outside the soft caps. One node today; a cap would be needed before more are added.

A node would need roughly 400+ paired seeds to be resolved, which is not practical (about 10 h per node set), so individual small nodes are judged by the analytic PE (exact, through the real soft cap) and the sim is used for groups. ## E. Earlier findings (2026-10-18, HEAD with EN3/EN4; bot sweeps are noisy: 48 seeds about +-7 pts per cell, 32 seeds about +-9)

1. **The weapon clusters are padding by construction.** Each weapon pool has face sum S about 20-22 against a cap of 7 (now 8.6): S/C is 2.3-3.1, past the 2 x cap saturation rule the validator already applies to the other categories (it skips the per-weapon pools). A cluster's 10-11 stat nodes together give about 0.6 PE, but the marginal node is worth 0.01 PE (about 0.1 % stat). The 54 'dead' rows below are dead INDIVIDUALLY (they add up to one cluster pool); removing a whole cluster still matters. Fixing it means either fewer/bigger nodes or a higher pool cap (a ceiling change); this chunk does not touch it.
2. **The full tree is about +10-11 % power.** Live combat PE 9.78 of the 13.18 live cap sum; the 2.0 PE lore + choice reserve belonged to inert nodes (Card Fan, Almanac, Hearth-key, Night Gate). Real effects of the whole tree: +1.8 % damage, +2 % cast speed, +2.9 % area, +4.7 % max HP, +4.7 % summon power, +3.9 % magic power, +6.6-7.7 % per weapon, bleed/burn +2.3 %.

4. **Hero gap is mostly hero baseline.** No tree, every gated weapon open, 96 seeds: Wren 2 %, Elias 8 %. Full tree: Wren 10 %, Elias 48 % (random, 48 seeds). The tree adds +8 and +40; sustain-only nodes add +2 / +2, the non-sustain rest +17 / +19, together +8 / +40, so the effect is multiplicative with survivability and Elias's orbit converts it. 5. **Ceiling what-if (data never shipped, scripts/review/impact-lib.mjs TREE_K): doubling every combat face and cap lifts random/FOCUS to Wren 40/58 and Elias 56/67 (48 seeds).** The tree needs about twice the current ceiling to land in the 45-55 / 65-75 band.

**Method.** Marginal PE = combat PE of the full live tree minus the PE of the same tree without that node, through the real soft cap C(1-e^(-S/C)) and category weights (a node in a saturated category is worth less than its face). Sustain PE uses the sustain weights (revive 4, reroll/banish 0.1 each, hearts). Class: strong >= 0.25 PE, medium >= 0.10, weak >= 0.03, dead < 0.03 with no option/utility value. Utility nodes (pickup, xp, gold, speed, ability cooldown) are judged by face / utility cap (medium >= 20%, weak >= 10%); perks, unlocks and visuals are `option`. Gates are not scored (they add content, not stats). Measured columns (if present) are paired-seed full-minus-node deltas: win points lost, damage dealt lost (+-1 SE).
